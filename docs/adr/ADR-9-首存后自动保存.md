# ADR-9：首存后自动保存（首次手动保存成功即启用 1/5 分钟自适应节拍）

> 本 ADR 规定：自动保存在用户**首次手动保存成功**之前保持关闭；此后启用，并对活动文档采用
> 「有改动 1 分钟 / 无改动 5 分钟」的自适应节拍。它细化 `ADR-7` 的自动保存条款，不推翻其「显式保存优先」的基线。

## Status / 状态

Accepted（代码引用见 `app/autosave_service.gd`、`ui/shell/file_coordinator.gd` 的 autosave 段、`ui/shell/main_window.gd:_gpAssembleCoordinators`）

本决策**细化** `ADR-7` 第 2 条「自动保存默认关闭」：关闭依旧是默认，但多了一条明确的启用触发点——首次手动保存成功。`ADR-7` 的第 1、3、4 条不受影响。

## Context / 背景

`ADR-7` 把「是否自动保存」默认置于关闭，理由是：P&ID 是工程交付物，意外的自动保存可能把未定稿状态固化为「已存盘」。但完全无自动保存又让「忘记按保存」直接丢进度——`ADR-7` 自己也承认这是「有意为之的取舍」。

两个事实让「永久关闭」过于保守：

1. **首次手动保存之前，本就没有文件可保护**。一个从未存过盘的文档没有目标路径，自动保存无处可写，也无从「误固化」——它连文件都还不存在。
2. **首次手动保存之后，用户已经明确表达过「这份内容值得落盘」**。此时再让「忘记按第二次保存」丢进度，收益（避免误固化）远小于代价（丢工作）。

因此「是否自动保存」不该是一个全程恒定的开关，而应有一个**自然的启用触发点：首次成功保存**。

## Decision / 决策

1. **启用触发点**：自动保存在**首次手动保存成功**（`gpWriteProject` 成功写盘、`gpCurrentPath` 确立）后启用；此前为关闭。启用是本会话内的单向闩锁，不因后续另存为而复位。
2. **自适应节拍**：
   - 文档**有未保存改动**（脏）→ 每 **1 分钟**自动保存一次；
   - 文档**无改动**（干净）→ 每 **5 分钟**自动保存一次（空闲复检）。
   节拍在脏标记翻转的瞬间重算，使新改动立即降到 1 分钟，而不必熬满空闲的 5 分钟。
3. **落盘即清脏**：自动保存写的是**权威本地文件**（复用 `ADR-4` 原子写 `tmp → 校验 → bak → rename`），因此写成功后清除脏标记——内容已与磁盘一致。这与 `ADR-7`「显式保存是唯一清脏路径」的表述相抵，故在此显式承接：自 `ADR-9` 起，**自动保存亦为一条合法清脏路径**。
4. **不覆盖「不保存」的意图**：退出三选一对话框打开期间，自动保存**暂停**；选「取消」后恢复节拍。否则后台保存会在用户选择「不保存」的瞬间从背后改写文件，使该选项失去意义。
5. **失败不降级为静默**：写盘失败（`ADR-4` 的 `GPIOResult` 非 OK）时保持脏标记不变、不退出、不改路径，等待下一拍重试；`ADR-4` 的 `.bak` 保留上一份完好副本作为安全网。
6. **策略与机制分离**：节拍策略（是否启用、用哪档）由纯 `RefCounted`（`GPAutoSaveService`）持有并 headless 单测；计时与落盘由文件协调者（真 `Timer` + 既有写入）承担。

## Consequences / 后果

- 正向：用户在首次保存后获得「忘记按保存也不会丢进度」的保护，无需任何额外设置；
- 正向：启用点天然——没有路径时不启用，杜绝了「新文档被自动写到错误路径」；
- 正向：1/5 分钟双档在「保护活动编辑」与「空闲不打扰」之间取平衡；
- 正向：暂停机制保住了「不保存」的语义，退出护栏与自动保存不互相拆台；
- 负向：`ADR-7` 的「显式保存是唯一清脏路径」不再字面成立（自动保存也清脏），文档标签的「脏」提示在自动保存后即消失——用户须以状态栏的「已自动保存」一行替代性地感知落盘时机；
- 负向：空闲 5 分钟复检会重复写入内容未变的文件（原子写，字节一致，仅更新 mtime）——换取「文件缺失/被外部移动时自动补写」的鲁棒性；
- 负向：`ADR-7` 提到的 `GPDocConfig` 配置类仍未实现，故 1/5 分钟目前是常量而非用户可调项；`GPAutoSaveService.gpConfigure()` 已为此预留入口。
