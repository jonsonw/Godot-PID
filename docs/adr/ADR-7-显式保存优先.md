# ADR-7：显式保存优先（Ctrl/Cmd+S 是唯一主保存路径）

> 本 ADR 规定：保存是显式的——`Ctrl/Cmd+S` 是唯一的主保存路径，自动保存默认关闭。

## Status / 状态

Accepted（代码引用见 `ui/shell/file_coordinator.gd:35`、`ui/shell/menu_coordinator.gd:66`、`ui/shell/menu_bar.gd:100`）

## Context / 背景

P&ID 是工程交付物，一次意外的自动保存可能把未定稿、甚至错误的状态固化为「已存盘」，给下游造成误判；反之，完全无自动保存又可能让用户忘记按保存键而丢失进度。两种极端的默认都不合适。

需要一条「用户掌控保存时机」的基线约定，把「是否自动保存」的开关默认置于关闭。

## Decision / 决策

1. **唯一主保存路径**：`Ctrl/Cmd+S` 是保存工程的主入口，用 Godot **全局 Shortcut** 注册，确保任何焦点状态下都能触发；
2. **自动保存默认关闭**：`GPDocConfig` 的自动保存选项默认 `false`；开启需用户显式勾选，且开启后仍有独立开关；
3. **未保存状态可感知**：编辑后状态栏 / 文档标签显示「脏」标记，提醒用户存在未落盘改动；
4. **导出 / 导入不改变保存语义**：`ADR-6` 的导入非破坏、`gpProjectExport` 的导出都走各自通道，不代替 `Ctrl+S` 的主保存。

## Consequences / 后果

- 正向：用户始终掌控存档时机，避免自动保存把未定稿状态误固化为交付物；
- 正向：保存路径单一，可审计、可挂撤销前的脏标记结算；
- 负向：用户「忘记按保存」会丢进度——这是有意为之的取舍，并以脏标记提醒缓解；
- 负向：自动保存作为可选能力，其实现（会话恢复 `session.json`、视图 sidecar）目前未接线，开启开关后行为需另行补全（见持久化实施计划）。
